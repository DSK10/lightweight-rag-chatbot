2. FIRST WEEK CHECKLIST
================================================================================

Day 1 — Welcome and Setup
  [ ] Complete WorkDay onboarding tasks
  [ ] Sign handbook, code of conduct, and security policy acknowledgments
  [ ] Receive laptop (pre-shipped for remote, in-person pickup for office)
  [ ] Set up Okta SSO and MFA (Okta Verify app required)
  [ ] Join Slack channels (see Section 4)
  [ ] Meet your manager (1:1, 30 min)
  [ ] Meet your onboarding buddy (1:1, 30 min)
  [ ] Company orientation (10:00 AM – 12:00 PM, all new hires)

Day 2 — Tools and Access
  [ ] GitHub Enterprise: verify org access (github.com/novatech-io)
  [ ] Jira/Confluence: verify project access
  [ ] AWS/GCP: verify IAM role assignment (via Okta)
  [ ] PagerDuty: account created (on-call training in Week 3)
  [ ] Datadog: read-only access granted
  [ ] 1Password: join Engineering vault
  [ ] Team intro meeting with your squad

Day 3 — Security and Compliance
  [ ] Complete Security Awareness Training (WorkDay Learning)
  [ ] Complete Secure Development Lifecycle (SDL) training
  [ ] Set up VPN (GlobalProtect) and verify connectivity
  [ ] Review Information Security Policy (SEC-ISP-2026-002)
  [ ] Enable full-disk encryption and verify CrowdStrike installed
  [ ] Submit SSH public key to GitHub (Ed25519 required, RSA deprecated)

Day 4 — Development Environment
  [ ] Clone team repositories (see Section 5)
  [ ] Run local development setup (team-specific README)
  [ ] Run test suite successfully (all green)
  [ ] Deploy to personal dev environment (staging namespace)
  [ ] Submit first PR (documentation fix or good-first-issue label)
  [ ] Attend team standup and introduce yourself

Day 5 — Culture and Process
  [ ] Read Engineering Handbook (Confluence: ENG/HANDBOOK)
  [ ] Review team sprint board and current sprint goals
  [ ] Schedule recurring 1:1 with manager (weekly, 30 min)
  [ ] Attend Engineering All-Hands (Fridays 4:00 PM UTC)
  [ ] Complete Week 1 onboarding survey (auto-sent via email)

6. DEVELOPMENT WORKFLOW
================================================================================

6.1 Sprint Process
  - 2-week sprints, starting Monday
  - Story points: Fibonacci (1, 2, 3, 5, 8, 13)
  - Velocity tracked per squad in Jira
  - WIP limit: 2 stories per engineer (max)

6.2 Pull Request Process
  1. Create branch from main
  2. Implement change with tests (80% coverage minimum)
  3. Run linters locally (pre-commit hooks enforce)
  4. Push and create PR with description template
  5. Request review from 1+ team member
  6. Address review comments
  7. CI must pass (build, test, lint, SAST, security scan)
  8. Squash merge to main
  9. Auto-deploy to staging
  10. Manual promote to production (via ArgoCD)

6.3 Code Review Guidelines
  - Review within 4 business hours
  - Be constructive and specific
  - Approve if changes are acceptable (don't block on style nitpicks)
  - Use "request changes" only for bugs, security issues, or missing tests
  - Pair on complex reviews when helpful

6.4 Testing Requirements
  - Unit tests: required for all new code
  - Integration tests: required for API changes
  - E2E tests: required for UI changes (Playwright)
  - Load tests: required for performance-critical changes
  - Test naming: TestFunctionName_Scenario_ExpectedResult

6.5 Deployment
  - Staging: auto-deploy on merge to main
  - Production: manual promotion, Tuesday/Thursday 2–6 AM UTC
  - Rollback: via ArgoCD (one-click) or revert commit
  - Feature flags: LaunchDarkly (all new features behind flags)

7. ON-CALL ROTATION
================================================================================

7.1 Overview
All E2+ engineers participate in on-call rotation. Rotation: 1 week, starting
Monday 9:00 AM local. Typical rotation size: 6–8 engineers per squad.

7.2 On-Call Compensation
  - Weekday on-call: $250/week stipend
  - Weekend on-call: $150/weekend stipend
  - Incident response: $100 per SEV-1/SEV-2 page (outside business hours)

7.3 On-Call Training
  - Shadow on-call for 1 week before first solo rotation (Week 3 of onboarding)
  - PagerDuty setup and escalation paths review
  - Runbook review for squad's services
  - Incident Commander training (E3+)

7.4 Escalation Path
  L1: On-call engineer (15 min response)
  L2: On-call engineer + squad lead (30 min)
  L3: On-call + VP Engineering + CTO (SEV-1 only)
  Security incidents: + CISO at L2

7.5 On-Call Best Practices
  - Keep laptop and phone charged and accessible
  - VPN configured and tested before rotation starts
  - Review recent incidents and runbooks before your week
  - Hand off open issues to next on-call in Slack #incidents
